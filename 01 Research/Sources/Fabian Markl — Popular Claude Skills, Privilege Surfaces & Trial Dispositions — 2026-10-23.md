## Cross-project findings HE can actually mine

### A. Classify intervention **before** installation

The 15 items span radically different privilege surfaces: (1) prose style rule, (2) progressive instruction skill, (3) helper/skill installer, (4) model API interception proxy, (5) Google-cookie authenticated service connector, (6) knowledge-graph indexer, (7) full always-on external-channel agent with filesystem mounts and messaging authority, and (8) binary/code analysis MCP. **“Paste repo link and ask Claude to install” is not a safe common installation contract.**

HE owner: **Skill Routing, Gate-Bound Evidence & Orthogonal Review**, already covers classification, allowed authority and minimal mechanism. New practical refinement: each evaluation should record *source SHA + execution class + client host + privilege/data flows + update/uninstall behavior + observable security enforcement*, not just SKILL.md presence.

### B. Discovering != installing != invoking != observing behavior

Vercel's `find-skills` and the skills.sh popularity list are **discovery** surfaces. Explicit allowed/install/activation/evaluation stages need separate owners. Skills.sh tracks aggregated installation telemetry and explicitly disclaims any guarantee of security or quality. Do not authorize programmatic auto-install or unpinned upgrades as a “smart router.” Check canonical paths, owner edits, symlink/copy and runtime-host policy composition if evaluating a small registry.

HE owner: **existing Agent Skills & Context Efficiency guidance**, skill routing, **ECC draft PR #20** EHE-05 refinement. No new skill-management platform without unmet need.

### C. Graph/source/reverse-engineering evidence must name its ceiling

- **Graphify:** `EXTRACTED` does not automatically equal *complete or correct*, and `INFERRED` must never be promoted to actual dependency or authority without source verification. Its `SECURITY.md` scopes local-only to code AST and calls out potential outbound model passes for other media. The prior HE A/B note already warns an extra graph layer may increase token/time cost.
- **REA:** black-box behavior, static structure and native pseudocode each imply different claims. Model-reconstructed implementations must be behaviorally compared against the **authorized test oracle**; unseen internal logic remains unknown. Local MCP means local tool execution, **not** that the agent provider will never receive extracted content.
- **Archify:** typed diagram and deterministic output validation can verify schema/renderer contract, not necessarily production-system truth; HE PR #7 already covers this.

HE owner: **Source Preservation & Evidence Durability**, **Artifact-Gated SDLC**, graph economics note, REA candidate assessment. No secondary graph store or mandatory reverse-engineering tool.

### D. “Small and containerized” does not imply operationally safe

NanoClaw's mount isolation and credential gateway are *promising architectural boundaries*, but evaluate the effective **container runtime flags, mounts, host credential storage, API gateway allowlists, egress, user/message trust and cancellation/restart semantics**. Untrusted messages remain injection-bearing input. Resource caps are opt-in, not protective defaults. “4,000 lines”/simplified architecture and successful demo are neither sandbox proof nor security certification.

HE owner: **Budgeted Side Effects, Approval Gates & Receipts** / **Supervised Agent Orchestration & Effect Verification** / EHE-05. Treat as **reference architecture** only; do not install always-on bots or connect personal or enterprise messaging/data as a research shortcut.

### E. Context compression is an acceptance-quality experiment, not a token marketing claim

Billion Context changes the agent's traffic and memory representation, not merely its style. Its README/Paper cites internal longitudinal data; **not independently replicated here**. A valid controlled test needs: mandatory-rule survival after compression, historical fact/authority recall, exact code/test task success, replay against known-bad cases, tool-schema parity, loss/recovery, input+output tokens, latency, monthly cost, and total human correction. License check must happen *before* integrating even for open-source HE.

HE owner: **Context Engineering**, **Derived Index Economics**, PMB governance; the **HE #21 audit** is relevant for the contrast between historical claims and current verified services. No always-on proxy insertion.

## Safety gates before any pilot installation

- **Supply chain:** explicit purpose, maintainer/repo identity, exact SHA or release + integrity, dependency inventory, license, install scripts, permissions, authentication and auto-update effects; sandbox/non-admin privilege; reversible uninstall and owner edits protected.
- **Data:** test on synthetic/public fixtures first; no employer-private records or credentials, uncontrolled browser cookies, raw agent transcripts or source trees passed to external services. Verify product/backend distinction and signed-in account handling.
- **Policy/authority:** original client host and adapter behavior checked, no shadow policy, no autonomous project-wide mutation, privilege upgrade, default tooling route or always-on egress. Local provider integration does not nullify model-provider data exposure.
- **Independent evaluation:** pre-register failure oracle and baseline, freeze before holdouts, report unsupported and negative results, no claim of efficacy from star counts or screenshots.
- **Reversibility:** documented toggles, what files/agent config are modified, target ownership, upgrade path, rollback and post-uninstall validation.
